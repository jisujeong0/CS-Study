## 1주차: 디자인 패턴과 프로그래밍 패러다임

### 1. 옵저버 패턴을 어떻게 구현하나요?
옵저버 패턴은 어느 객체의 상태가 변경되면, 그 객체에 의존하는 다른 객체들에게 상태 변화를 알려주는 패턴이다.

인터페이스로 주체와 옵저버를 정의하고, 해당 인터페이스를 각각 받아서 클래스로 구현한다.
주체에는 옵저버를 등록하는 registerObserver, 옵저버를 삭제하는 removeObserver, 옵저버에게 상태 변화를 알리는 notifyObserver를 구현한다.
옵저버는 주체의 상태 변화를 받아 업데이트하는 update를 구현해준다.

### 2. 프록시 서버를 설명하고 사용 사례에 대해 설명해보세요.
프록시 서버는 진짜 객체를 대신하여 작업을 처리하는 서버다.

주로 진짜 객체에 대한 접근을 제어하는 역할을 하는데, 접근 제어 방식은 크게 3가지가 존재한다. 원격 프록시, 가상 프록시, 보호 프록시로, 순서대로 다른 주소에 있음에도 로컬 환경인 것처럼 작동하게 하고, 비용이 큰 객체의 생성을 가능한 만큼 지연하고 대신 작업을 처리하거나, 진짜 객체에 접근할 객체를 선별해 접근 권한을 준다.
대표적인 예시는 Node.js의 nginx가 있다.

### 3. MVC 패턴을 설명하고 MVVM 패턴과의 차이는 무엇인지 설명해보세요.
MVC 패턴은 Model, VIew, Controller로 구성되어 있다. Model은 상수나 변수같은 데이터를 담당한다, View는 화면에 표시하는 정보로, 변경되면 컨트롤러에 알려야 한다. Controller는 모델과 뷰를 이어주는 역할을 한다.

MVVC 패턴은 Controller 대신 View Model을 사용한다. 여기서 View Model은 View를 추상화한 버전이며, View를 관리하는 역할을 하고, 데이터 바인딩을 통해 뷰와 뷰 모델은 자동으로 동기화된다.
