## **3\. 절차형 프로그래밍**

절차형 프로그래밍은 명령형 패러다임의 일종으로, 어떻게 할 것인가에 가깝다.

절차형은 위에서 아래로, 로직에 따라 코드의 **순차적인 처리가 중요시되고** 프로그램 전체가 **유기적으로 연결**되도록 하는 프로그래밍 패러다임이다.

### ✨ 절차형 프로그래밍의 특징

-   컴퓨터와 유사한 처리구조의 코딩방식이므로 실행 속도가 빠르다는 장점이 있다.
-   유지보수가 어렵고, 코드의 실행 순서가 정해져 있으므로 코드의 순서가 바뀌면 동일한 결과를 보장하지 못한다.

<br>

## **4\. 패러다임의 혼합**

> 하나의 프로그램에서 여러 프로그래밍 패러다임을 목적에 맞게 함께 쓰는 것

#### 🤔 왜 혼합해야 할까?

****→**  한 패러다임이 모든 문제를 다 잘 풀진 못함**

-   비즈니스 규칙 → 객체지향이 좋음
-   데이터 변환 → 함수형이 깔끔함
-   흐름 제어 → 절차지향이 직관적

👉 그래서 **장점만 골라 씀**

```
// 객체지향 + 절차
class Game {
    void run() {
        init();
        start();
        end();
    }
}

// 전체 흐름: 절차적
// 내부 상태: 객체
```

최고의 패러다임은 없다. 비즈니스 로직과 서비스의 특징을 고려하여 패러다임을 고를 것!
