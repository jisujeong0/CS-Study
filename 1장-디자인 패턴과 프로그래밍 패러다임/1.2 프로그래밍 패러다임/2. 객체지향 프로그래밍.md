## **2\. 객체지향 프로그래밍(OOP, Object-Oriented Programming)**

> 🤔 객체지향적 사고를 하라는 말을 많이 듣는다. **객체지향적**이라는 게 도대체 뭘까?

객체지향 프로그래밍은 프로그램을 여러 객체들의 협력으로 보고, 데이터와 그 데이터를 다루는 메소드를 하나의 객체로 묶어 객체 간 메서드 호출을 통해 프로그램을 구성하는 방식이다.

✅**많은 시간 소요, 타 프로그래밍 패러다임에 비해 느린 처리 속도**

### ✨ 객체지향 프로그래밍의 특징

**추상화:** 복잡한 시스템으로부터 핵심적인 개념 또는 기능을 간추려내는 것

```
interface Payment {
    void pay();
}
```

```
class CardPayment implements Payment {
    public void pay() {}
}

class KakaoPay implements Payment {
    public void pay() {}
}
```

**캡슐화:** 객체의 속성과 메소드를 하나로 묶고 일부를 외부에 감추어 은닉하는 것

**상속성:** 상위 클래스의 특성을 하위 클래스가 이어받아 재사용하거나 추가, 확장하는 것

```
class Animal {
    void sound() {}
}

class Dog extends Animal {
    void sound() {
        System.out.println("멍멍");
    }
}
```

**다형성:** 하나의 메소드나 클래스가 다양한 방법으로 동작하는 것 ex. 오버로딩, 오버라이딩

```
Payment payment = new CardPayment();
payment.pay();

payment = new KakaoPay();
payment.pay();
```

### ✅ SOLID 원칙:

객체지향 프로그래밍을 할 때 지켜야 할 원칙

#### SRP, Single Resoponsibility Principle

단일 책임 원칙: 모든 클래스는 각각 하나의 책임만 가져야 한다.

-   클래스가 바뀌어야 할 이유는 하나여야 한다.

#### OCP, Open Closed Principle

개방-폐쇄 원칙: 확장에는 열려있어야 하고, 수정에는 닫혀있어야 한다.

-   기능을 추가할 때 기존 코드를 고치지 않게 설계해야 한다.

#### LSP, Liskov Substitution Principle

리스코프 치환 원칙: 프로그램의 객체는 프로그램의 정확성을 깨트리지 않으면서 하위 타입의 인스턴스로 바꿀 수 있어야 하는 것을 의미한다.

-   자식 클래스는 부모 클래스를 대체할 수 있어야 한다.
-   하위 클래스가 상위 클래스의 기능을 변경하면 안 된다.

#### ISP, Interface Segregation Principle

인터페이스 분리 원칙: 하나의 일반적인 인터페이스보다 구체적인 여러 개의 인터페이스를 만들어야 한다.

-   사용하지 않는 인터페이스에 의존하지 않도록 해야 한다.
-   하나의 큰 인터페이스보다는 여러 개의 작은 인터페이스로 분리하는 것이 좋다.

#### DIP, Dependency Inversion Principle

의존 역전 원칙: 자신보다 변하기 쉬운 것에 의존하던 것을 추상화된 인터페이스나 상위 클래스를 두어 변하기 쉬운 것의 변화에 영향받지 않게 하는 원칙.

-   상위 모듈이 하위 모듈에 의존하는 것이 아니라, 하위 모듈이 상위 모듈에 의존해야 한다.
