## **3\. 전략 패턴**

> 알고리즘군을 정의하고 각각을 **캡슐화**하여 교환해서 사용할 수 있도록 만든다.  
> 전략 패턴을 활용하면 알고리즘을 사용하는 클라이언트와는 독립적으로 알고리즘을 변경할 수 있다. 이 캡슐화한 알고리즘을 **전략**이라고 부른다.

<br>

> **CODE: 오리 정의하기**

어느 오리 캐릭터를 만드는 회사가 있다. 모든 오리들은 날 수 있고, 꽥 소리를 낸다.(아래 코드에서는 Quack 메소드에 대한 부분은 제외했다)

그럼 모든 오리 캐릭터가 Duck이라는 추상 클래스를 상속하면 되지 않을까? 맞다.

**그런데** 어느 날, 날지 않는 오리 장난감 캐릭터를 만들어달라는 요구가 도착했다. 이제 어떻게 해결해야 할까?

```
1️⃣ Duck mallard = new MallardDuck();
2️⃣ mallard.performFly();
```

책에는 performQuack도 있었는데, 코드의 길이를 위해 제외했다.

> **전략: 날거나 날지 않는 오리의 행동**

```
public interface FlyBehavior {
	public void fly();
}

public class FlyWithWings implements FlyBehavior {
	public void fly() { // 코드 }
}

public class FlyNoWay implements FlyBehavior {
	public void fly() { // 코드 }
}
```

전략인 FlyBehavior다. 나는 행위가 캡슐화되어있다. 오리가 날거나 날지 않음을 정의하고 있다. 

> **오리**

```
public abstract class Duck {
    FlyBehavior flyBehavior;

    public duck() {}
    
    public abstract display();
    
    public void performFly() {
        flyBehavior.fly();
    }
}
```

```
public class MallardDuck extends Duck {
	public MallardDuck() {
    	    flyBehavior = new FlyWithWings();
        }

	public void display() { 
            // 코드 
    	}
}
```

Duck을 상속받는 여러 오리들은 flyBehavior에서 FlyWithWings이나 FlyNoway를 선택한다. 이렇게 하면 날지 않는 오리도 Duck을 상속받아 구현할 수 있다.
