## 2️⃣ 전송 계층

👉 **애플리케이션 간 “끝과 끝” 통신을 책임지는 계층**

-   송신 프로그램 ↔ 수신 프로그램
-   데이터가 **정확하게, 순서대로, 필요시 빠르게** 전송되도록 관리

> 📌 OSI 모델에서는 **Transport 계층** 

#### 전송 계층의 대표 프로토콜

| **구분** | **TCP** | **UDP** |
| --- | --- | --- |
| 연결 방식 | 연결 지향 | 비연결 |
| 패킷 교환 방식 | 가상회선 방식 | 데이터그램 방식 |
| 신뢰성 | 높음 | 낮음 |
| 순서 보장 | O | X |
| 재전송 | O | X |
| 흐름 제어 | O | X |
| 혼잡 제어 | O | X |
| 속도 | 느림 | 빠름 |

## TCP (Transmission Control Protocol)

> 📌 “전화 통화 전에 연결 확인하고 말하는 방식”

-   데이터가 **유실 없이 /** **순서대로 /** **중복 없이** 도착하도록 보장

👉 **신뢰성 있는 데이터 전송을 위한 프로토콜**

#### **특징**

-   **가상회선 패킷 교환 방식**
-   **연결 지향 (3-way handshake)**
-   순서 보장
-   재전송
-   흐름/혼잡 제어

**사용 예:** HTTP, HTTPS / FTP / SMTP

> **가상회선 패킷 교환 방식?**  
> 👉 통신 전에 논리적인 경로(회선)를 미리 설정  
> 👉 모든 패킷이 같은 경로로 이동

> **패킷 교환방식?** 데이터를 일정한 크기의 패킷으로 분할하여 네트워크를 통해 전송하는 방식.

## UDP (User Datagram Protocol)

> 📌 “확인 안 하고 소리치는 방식”

👉 **빠른 데이터 전송을 위한 프로토콜**

**특징**

-   데이터그램 패킷 교환 방식 
-   비연결형
-   순서 보장 ❌
-   재전송 ❌
-   오버헤드 작음

**사용 예:** 스트리밍 / 게임 / DNS

> **데이터그램 패킷 교환 방식?**  
> 👉 연결 설정 없이 각 패킷을 독립적으로 전송  
> 👉 각기 다른 경로를 통해 목적지에 도달
