## 4️⃣ 링크 계층

> MAC 주소를 사용해 같은 네트워크 내에서 프레임을 실제 매체로 전송하는 계층

> 📌 OSI로는 **데이터 링크 + 물리 계층**

### 🔗 링크 계층의 역할

-   같은 네트워크(LAN) 내 장치 간 데이터 전달
-   IP 패킷을 **프레임**으로 캡슐화
-   **MAC 주소 기반 통신**
-   물리 매체(전선, 전파)를 통해 실제 전송

#### 전이중화 / 반이중화 통신

| 구분 | 반이중화 | 전이중화 |
| --- | --- | --- |
| 동시 송수신 | X | O |
| 충돌 | 있음 | 없음 |
| 효율 | 낮음 | 높음 |
| 사용 예 | 허브 | 스위치 |

### 전이중화 (Full Duplex)

> 양쪽 장치가 동시에 송신과 수신이 가능한 통신 방식  
> 말하는 동시에 들을 수 있는 통신 ex. 전화 통화

👉 **양방향 동시 통신 가능**

#### 특징:

-   **통신 효율이 높음** → 데이터 충돌이 거의 없음
-   **장치 비용** → 회선이 2개 필요하거나, 한 회선에서 양방향 신호를 분리해야 하므로 약간 비쌈

### 반이중화 (Half Duplex)

> 한 번에 한쪽 방향으로만 통신 가능  
> 즉, 송신과 수신을 번갈아가며 수행 ex. 무전기

👉 **양방향 가능하지만 동시에 X**

특징:

-   충돌 가능
-   통신 회선을 **공유** → 장치 비용 낮음
-   **동시 송수신 불가** → 효율이 떨어질 수 있음
-   CSMA/CD 사용

> ✨🤔 전이중화/반이중화 방식이 유/무선 LAN과 무슨 관련이지?

#### ✅ 핵심:

-   유선 LAN은 기술과 환경에 따라 전이중/반이중이 가능
-   무선 LAN은 구조상 항상 반이중으로 동작

| **구분** | **LAN 유형** | **접근 방식** | **충돌 처리** |
| --- | --- | --- | --- |
| 유선 LAN | Ethernet | CSMA/CD | 충돌 감지 후 재전송 |
| 무선 LAN | Wi-Fi | CSMA/CA | 충돌 회피, ACK 확인 |

### 1️⃣ CSMA/CD (Carrier Sense Multiple Access with Collision Detection)

> 유선 LAN(Ethernet)에서 사용되는 접근 제어 방식  
> 동시에 여러 장치가 데이터를 보내려고 하면 충돌이 발생할 수 있는데, 이를 감지하고 처리하는 방법

**동작 원리**

1.  장치가 전송하기 전에 **회선을 듣는다(Carrier Sense)**
    -   다른 장치가 데이터 전송 중이면 기다림
2.  만약 동시에 데이터 전송 → **충돌 감지(Collision Detection)**
3.  충돌 발생 시, 장치는 **랜덤 시간 후 재전송**

**특징**

-   **유선 LAN에서 사용** (Ethernet)
-   회선이 공유되므로 충돌 가능성이 있음
-   장점: 충돌 감지 후 재전송 → 안정적
-   단점: 충돌이 많으면 효율 ↓

### 2️⃣ CSMA/CA (Carrier Sense Multiple Access with Collision Avoidance)

> 무선 LAN(Wi-Fi)에서 사용되는 접근 제어 방식  
> 충돌 감지가 어려운 무선 환경에서 충돌 발생 자체를 미리 방지

**동작 원리**

1.  장치가 전송 전에 **회선을 듣는다(Carrier Sense)**
    -   무선에서는 상대방 신호가 안 들릴 수도 있음
2.  송신 전에 **랜덤 백오프 시간** 대기
    -   동시에 여러 장치가 전송하려는 경우 충돌 가능성 최소화
3.  필요 시 **ACK(응답) 신호**로 성공 여부 확인

**특징**

-   **무선 LAN에서 사용**
-   충돌 감지가 어렵기 때문에 미리 회피 전략 사용
-   예: IEEE 802.11 (Wi-Fi)

---

#### BSS (Basic Service Set)

> 무선 LAN(Wi-Fi)의 가장 작은 통신 단위  
> 하나의 AP(Access Point)와 연결된 클라이언트 장치(STA, Station)들의 집합

#### ESS (Extended Service Set)

> 여러 BSS를 하나로 묶은 큰 무선 LAN 영역  
> 즉, 복수 AP를 통해 무선 커버리지를 확장한 네트워크

> BSS:  AP 한 대와 연결된 장치 집합 (작은 단위)  
> ESS: 여러 BSS를 묶어서 범위를 확장한 전체 무선 네트워크 (큰 단위, 로밍 가능)

---

#### 이더넷 프레임

> 이더넷에서 데이터를 전송할 때, 물리적 매체를 통해 보내는 데이터 단위  
> 쉽게 말해, 네트워크에서 장치 간 주고받는 “패키지”

전송 효율과 충돌 관리를 위해 **정해진 구조**를 가지고 있음

#### 구조 (대표적인 IEEE 802.3 기준)

| **필드**  | **길이** | **설명** |
| --- | --- | --- |
| **Preamble + SFD** | 8바이트 | 수신 장치 동기화용. SFD(Start Frame Delimiter)로 프레임 시작 표시 |
| **Destination MAC** | 6바이트 | 목적지 장치의 MAC 주소 |
| **Source MAC** | 6바이트 | 송신 장치의 MAC 주소 |
| **Type / Length** | 2바이트 | 상위 계층 프로토콜 타입(IP, ARP 등) 또는 데이터 길이 |
| **Data / Payload** | 46~1500바이트 | 실제 전송할 데이터 (IP 패킷 등) |
| **FCS(Frame Check Sequence)** | 4바이트 | 오류 검출용 CRC(Cyclic Redundancy Check) |

### ⛓️‍💥 계층 간 데이터 송수신 과정

#### **송신 (Encapsulation)**

> 캡슐화 과정: 상위 계층의 헤더와 데이터를 하위 계층의 데이터 부분에 포함시키고 해당 계층의 헤더를 삽입하는 과정

```
Application  → 데이터
Transport    → 세그먼트 (TCP/UDP 헤더)
Internet     → 패킷 (IP 헤더)
Link         → 프레임 (MAC 헤더)
Physical     → 비트
```

#### **수신 (Decapsulation)**

> 비캡슐화 과정: 하위 계층에서 상위 계층으로 가며 각 계층의 헤더 부분을 제거하는 과정

```
Physical     → 비트 수신
Link         → 프레임 해제
Internet     → IP 헤더 제거
Transport    → TCP/UDP 처리
Application  → 데이터 전달
```

**PDU = Protocol Data Unit (프로토콜 데이터 단위)**

-   네트워크 계층별로 **전송되는 데이터 단위**를 의미합니다.
-   애플리케이션 계층: 메시지
-   전송 계층: 세그먼트(TCP), 데이터그램(UDP)
-   인터넷 계층: 패킷
-   링크 계층: 프레임(데이터 링크 계층), 비트(물리 계층)
