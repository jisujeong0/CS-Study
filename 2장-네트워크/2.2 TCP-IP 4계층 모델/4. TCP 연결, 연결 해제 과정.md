## TCP 연결 / 연결 해제 과정

### 1️⃣ 연결 성립 과정: 3-Way HandShake 

> 총 3번의 패킷 교환 →  3-Way

👉 TCP에서 통신을 시작하기 전에 상호 간에 **연결할 준비가 됐는지** 확인하는 과정

-   SYN\_RCV: SYNC 요청을 받고 상대방의 응답을 기다리는 중
-   ESTABLISHED: 포트 연결 상태

#### 과정 설명

**1️⃣ SYN** (클라이언트 → 서버)

-   SYN: 연결 설정을 요청하는 패킷, 세션을 설정하는데 사용되며 초기에 시퀀스 번호를 보냄

**2️⃣ SYN + ACK** (서버 → 클라이언트)

-   클라이언트에서 보낸 SYN 확인 후, 패킷을 받았다는 의미의 ACK 패킷을 클라이언트로 전송
-   클라이언트로 SYN 패킷 전송

3️⃣ **ACK** (클라이언트 → 서버)

-   ACK 패킷을 서버로 전송

📌 여기서 **연결 성립.**

**📌 3-Way HandShake 과정이 있어 TCP는 신뢰성이 있는 계층.**

> **💡 SYN Flood 공격:** TCP 3-way handshake의 약점을 이용한 DoS 공격

> **💥 공격 방식:**  
> 1️⃣ 공격자가 서버에 SYN 폭탄 전송  
> 2️⃣ 서버는 SYN+ACK 응답  
> 3️⃣ 공격자는 ACK 안 보냄

> **📌 서버 상태:**  
> 연결 대기 상태(SYN\_RECEIVED)가 계속 쌓임  
> 연결 테이블 가득 참  
> 정상 사용자 접속 불가 ❌

▶️ 서버는 **연결 상태를 기억하기 때문에** ACK 안 와도 기다림 -> 리소스 고갈

### 2️⃣ 연결 해제 과정: 4-Way HandShake 

> TCP는 양방향 통신이라 클라이언트 종료와 서버 종료를 따로 처리함

**1️⃣ FIN** (클라이언트 → 서버)

-   FIN: 연결 해제. 세션 연결을 종료시킬 때 사용되며, 더 이상 전송할 데이터가 없음을 의미

**2️⃣ ACK** (서버 → 클라이언트)

-   패킷을 받았다는 의미의 ACK 패킷을 클라이언트로 전송

**3️⃣ FIN** (서버 → 클라이언트)

-   세션 연결 종료를 위해 클라이언트에 FIN 패킷을 전송

**4️⃣ ACK** (클라이언트 → 서버)

-   패킷을 받았다는 의미의 ACK 패킷을 서버로 전송

📌 **이때 연결 종료**

###  TIME\_WAIT 상태 

> 마지막 ACK 보낸 쪽은 잠깐 기다림, 일정 시간 후에 종료하기 위해

-   **지연 패킷이 발생할 경우 대비:** 패킷이 뒤늦게 도달하고 이를 처리하지 못한다면 데이터 무결성 문제 발생
-   **두 장치의 연결이 닫혔는지 확인하기 위함:** LAST\_ACK 상태에서 닫힐 경우 새로운 연결을 시도할 때 접속 오류 발생
