## 네트워크란?

> 노드와 링크가 서로 연결되어 있거나 / 연결되어 있으며 리소스를 공유하는 집합

**노드:** 서버, 라우터, 스위치 등의 네트워크 장치

**링크:** 유선 또는 무선

##  좋은 네트워크란? 

> **많은 처리량(Throughput)** 과 **짧은 지연 시간(Latency)**, 데이터 전송 중 손실이 거의 없고 장애 발생 시 신속하게 복구되는 안정적이고 신뢰할 수 있는 환경

### 🥊 처리량과 지연 시간 비교

| **구분** | **처리량** | **지연 시간** |
| --- | --- | --- |
| 의미 | 얼마나 많이 | 얼마나 빨리 |
| 주된 영향 | 대역폭, 트래픽 | 거리, 큐잉 |
| 트래픽 증가 시 | 감소 가능 | 증가 |

<br>

## 1️. 처리량

> 링크 내에서 성공적으로 전달된 데이터의 양. 얼만큼의 트래픽을 처리했는지

**많은 트래픽을 처리한다 = 많은 처리량을 가진다.**

> **💡 트래픽과 처리량이 같은 말인가?**  
> **그건 아니다.** 트래픽이 많아졌다는 것은 흐르는 데이터가 많아졌다는 뜻이고, 처리량이 많아졌다는 건 처리하는 트래픽이 많아졌다는 뜻이다.

> **대역폭?**  
> 주어진 시간 동안 네트워크 연결을 통해 흐를 수 있는 최대 비트 수

#### **처리량의 단위**
bps(bits per second)를 사용하며, 초당 전송 또는 수신되는 비트 수를 의미한다.

### ✨ 처리량에 영향을 주는 요소

| **요소** | **처리량에 미치는 영향** |
| --- | --- |
| 트래픽 | 많아지면 혼잡 → 처리량 감소 |
| 대역폭 | 처리량의 최대 한계 |
| 에러 | 재전송 증가 → 처리량 감소 |
| 하드웨어 스펙 | 병목 발생 시 처리량 제한 |

#### 1️⃣ 트래픽 (Traffic)

> 네트워크에 몰리는 데이터 양

| 트래픽이 적을 때 | 데이터가 문제없이 흐름 |
| --- | --- |
| 트래픽이 많을 때 | **대기, 지연, 패킷 손실 발생** |

**결과: 트래픽이 많아지면?**

-   패킷 재전송 증가
-   큐(버퍼)에 쌓였다가 버려짐 👉 **처리량 감소**

> **트래픽이 많아질수록 처리량은 일정 시점부터 오히려 줄어든다!**

#### 2️⃣ 네트워크 장치 간의 대역폭

> 한 번에 보낼 수 있는 최대 용량  
> 아무리 데이터가 많아도 대역폭이 적으면 그만큼밖에 못 보냄


-   서버 ↔ 서버 대역폭이 100Mbps
-   클라이언트가 아무리 빨라도 👉 **처리량 최대치는 100Mbps**가 한계

> **처리량의 상한선은 대역폭이 정한다!**

#### 3️⃣ 네트워크 중간에 발생하는 에러

> 패킷 손실, 충돌, 노이즈 등

#### 4️⃣ 장치의 하드웨어 스펙

> CPU, 메모리, NIC 성능

네트워크는 결국 장치가 처리하기 때문에, **하드웨어 스펙도 영향을 미친다.**

-   CPU 부족 → 패킷 처리 못 따라감
-   메모리 부족 → 버퍼 부족 → 패킷 드롭
-   NIC(네트워크 카드) 성능 낮음 → 초당 처리 가능한 패킷 수 한계

> **네트워크가 아니라 장치가 병목일 수도 있다!**

<br>

## 2️. 지연 시간

> 요청이 처리되는 시간 (어떤 메시지가 두 장치 사이를 왕복하는 데 걸린 시간)

### ✨ 지연 시간에 영향을 주는 요소

#### 1️⃣ 매체 타입 (유선 / 무선)

> **유선 (광케이블, 이더넷) 👉** 지연시간이 짧고 일정

> **무선 (와이파이, LTE, 5G)** 👉 지연시간이 길어지고 들쭉날쭉

#### 2️⃣ 패킷 크기

-   패킷이 크면 전송하는 데 시간이 더 걸림 / 큐(대기열)에 오래 머묾
-   패킷이 작으면 전송과 처리가 빠름

#### 3️⃣ 라우터의 패킷 처리 시간

**라우터가 하는 일:** 목적지 IP 확인 / 라우팅 테이블 조회 / 방화벽 / QoS 검사

-   트래픽 많으면 → 대기 시간 증가
-   성능이 낮은 라우터 → 처리 느림
