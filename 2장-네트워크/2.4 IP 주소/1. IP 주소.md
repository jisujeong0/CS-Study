> **IP = Internet Protocol**  
> 인터넷이나 네트워크에 연결된 장치 하나하나를 식별하기 위한 고유한 주소
​
## IP 주소 체계

### 1️⃣ IPv4

> 32비트를 8비트 단위로 점을 찍어 표기  

-   **형식:** 4개의 숫자, 각각 0~255 → 192.168.1.1
-   **예시:**
    -   192.168.1.10/24
        -   /24 → 서브넷 마스크, 네트워크 주소가 24비트
        -   네트워크 주소: 192.168.1.0
        -   호스트 주소: 10

### 2️⃣ IPv6
> 64비트를 16비트 단위로 점을 찍어 표기
​
-   IPv4가 부족해 생긴 확장형 주소
-   형식: 128비트, 16진수 8블록 → 2001:0db8:85a3:0000:0000:8a2e:0370:7334
-   훨씬 많은 장치를 식별 가능

### 3️⃣ 클래스 기반 할당 방식
**구성**
    
1. **구분 비트**: 클래스 간의 IP를 구분하여 주소 범위 지정
2. **네트워크 주소(Network)**: 어느 네트워크에 속하는지
3. **호스트 주소(Host)**: 네트워크 안에서 특정 장치 식별


클래스 A, B, C는 일대일 통신으로 사용되고, 클래스 D는 멀티캐스트 통신, 클래스 E는 앞으로 사용할 예비용이다.

▶️ **단점: 사용하는 주소보다 버리는 주소가 많음,** 이를 해결하기 위해 **DHCP, IPv6, NAT**가 나왔다.

​
### ARP (Address Resolution Protocol)

> **IP 주소 → MAC 주소로 변환**하는 프로토콜  
> LAN 내부에서 데이터를 정확한 장치로 보내기 위해 필요하다.


### RARP (Reverse ARP)
> RARP는 **MAC 주소 → IP 주소로 변환**하는 프로토콜  
> 주로 자신의 IP 주소를 모르는 장치가 부팅할 때 사용한다.

| **구분** | **ARP** | **RARP** |
| --- | --- | --- |
| 변환 방향 | IP → MAC | MAC → IP |
| 목적 | 데이터를 올바른 장치로 전달 | IP 주소를 모르는 장치에 IP 할당 |
| 사용 위치 | LAN 내부 | 부팅 시 IP 없는 장치 |
| 사용 여부 | 현재도 활발히 사용 | 거의 사용 안함, DHCP로 대체 |
| 요청 방식 | 브로드캐스트 | 브로드캐스트 |
​
### DHCP (Dynamic Host Configuration Protocol)
> 동적 호스트 구성 프로토콜  
> 네트워크 장치가 자동으로 IP 주소와 네트워크 정보를 할당받게 해주는 프로토콜

▶️ 네트워크 장치의 IP주소를 수동으로 설정할 필요없이 인터넷에 접속할 때마다 자동으로 할당

| **구분** | **RARP** | **DHCP** |
| --- | --- | --- |
| 목적 | MAC → IP | IP, 서브넷, 게이트웨이, DNS 등 자동 설정 |
| 사용 범위 | IP만 제공 | IP + 네트워크 설정 전체 |
| 현대 사용 | 거의 없음 | 널리 사용 (가정, 기업 LAN) |
​
### NAT (Network Address Translation)

> 패킷이 라우팅 장치를 통해 전송되는 동안, 패킷의 IP 주소를 수정하여 IP 주소를 다른 주소로 매핑하는 방법

IP주소의 단점 탓에(많은 주소를 모두 감당하지 못함) NAT로 **공인 IP와 사설 IP로** 나눠서 많은 주소를 처리한다.

ex. ICS, RRAS, Netfilter

### 홉바이홉(hop by hop) 통신

> 데이터를 출발지에서 목적지까지 한 번에 전달하지 않고, 중간 장치를 거치면서 단계별로 전달하는 통신 방식.
> **IP 주소를 통해 통신한다.**

> ▶️ 통신 장치에 있는 '라우팅 테이블'의 IP를 통해 시작 주소부터 다음 IP로 계속해서 이동하는 '라우팅' 과정을 거쳐 패킷이 최종 목적지까지 도달하는 통신

-   Hop(홉) = **중간 장치(라우터, 스위치 등)를 한 번 통과하는 과정**
-   즉, 데이터가 A → B → C → D 로 갈 때, A→B, B→C, C→D 각각을 한 홉(Hop)이라고 한다.
    ​
> **라우팅 테이블:**  
> 라우터에 들어가 있는 목적지 정보들과 그 목적지로 가기 위한 방법이 들어있는 리스트.  
> 패킷을 어디로 보내야 하는지 결정하기 위해 참조하는 정보를 담은 표. 게이트웨이와 모든 목적지에 대해 해당 목적지에 도달하기 위해 거쳐야 할 다음 라우터의 정보를 가지고 있다.

> **게이트웨이:**  
> 서로 다른 통신망, 프로토콜을 사용하는 네트워크 간 통신을 가능하게 하는 관문 역할.

| **구분** | **홉바이홉** | **엔드투엔드** |
| --- | --- | --- |
| 데이터 처리 | 각 홉에서 처리 (패킷 헤더 확인, 경로 결정) | 출발지에서 목적지까지 한 번에 처리 (예: TCP 오류 체크) |
| 오류 처리 | 홉 단위로 오류 검사 가능 | 출발지↔목적지 단위로 오류 처리 |
| 예시 | IP 라우팅, MPLS, 일부 QoS | TCP, 애플리케이션 계층 |

### 엔드투엔드(End-to-End) 통신

> 데이터를 송신자에서 수신자까지 직접 전달하고,  
> 중간 장치(라우터, 스위치 등)는 단순 전달만 수행하는 통신 방식입니다.

▶️ 즉, **중간 장치는 데이터 내용에 관여하지 않고**, **목적지까지 정확하게 전달되도록 보장하는 책임은 송신자와 수신자**가 가짐
